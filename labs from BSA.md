## Лабораторная работа №1. Семантическая вёрстка. Страница-резюме

**Цель:** научиться размечать страницу семантическими тегами HTML5 и располагать блоки с помощью Flexbox без использования float и абсолютного позиционирования.

**Что нужно сделать:**
Сверстать одностраничное резюме/портфолио (можно про себя, можно про вымышленного персонажа). Страница обязана содержать следующие блоки:

1. **Шапка (`<header>`)** — имя, должность/специальность, короткий слоган.
2. **Фотография/аватар** — любое изображение (можно placeholder, например через `https://i.pravatar.cc/300`).
3. **Блок «О себе» (`<section>` или `<article>`)** — 3–5 предложений биографии.
4. **Блок «Образование»** — список (`<ul>`/`<ol>`) с местом и годами обучения.
5. **Блок «Навыки»** — список в виде тегов/чипсов (например, каждый навык — `<span class="skill">`, оформленный как «пилюля» с фоном и скруглением).
6. **Блок «Контакты» (`<footer>` или отдельная `<section>`)** — минимум 3 интерактивные ссылки: `mailto:`, ссылка на соцсеть/GitHub, ссылка на телефон (`tel:`). Ссылки должны иметь ховер-эффект (смена цвета/подчёркивания через `:hover`).
7. **Навигация (`<nav>`)** — если страница длинная, добавить якорные ссылки на блоки (`<a href="#skills">`).

**Технические требования (обязательные):**
- Ровно один файл `index.html` и один файл `style.css` в папке `task1/`. Никакого JavaScript.
- Стили — во внешнем файле `style.css`, инлайн-стили (`style="..."`) и `<style>` внутри HTML — не использовать (кроме исключительных случаев, которые нужно уметь объяснить)
- Верный HTML5-доктайп с указанием языка и initial-scale.
- Использовать **только семантические теги** для структуры: `<header>`, `<main>`, `<section>`, `<article>`, `<nav>`, `<footer>`. Использование «голого» `<div>` для структурных блоков — _минус к оценке_ (внутри блоков `<div>` для вспомогательной вёрстки — можно).
- Вся раскладка блоков (расположение секций друг относительно друга, выравнивание элементов внутри блока) — **только через `display: flex`**. Использование `float` или `position: absolute/fixed` для основной раскладки — запрещено. (Точечное использование `position: relative` для мелких декоративных элементов допустимо.)
- Обязательно продемонстрировать в CSS: `justify-content`, `align-items`, `flex-direction`, `flex-wrap`, `gap`.
- `box-sizing: border-box` должен быть выставлен глобально.

**Что можно НЕ делать:** не требуется адаптивность под мобильные устройства и медиазапросы — это следующая лабораторная. 

**Что сдавать:** папку `task1/` с `index.html`, `style.css`, изображениями (если локальные). Работа должна открываться через GitHub Pages по ссылке `.../task1/`.

**Критерии проверки:** валидная семантическая структура, отсутствие float/absolute в раскладке, использование Flexbox с как минимум 4 разными свойствами, отсутствие инлайн-стилей, страница открывается без ошибок в консоли.

## Лабораторная работа №2. Адаптивная вёрстка. Лендинг по макету

**Цель:** освоить CSS Grid, подход Mobile First и медиазапросы для адаптации под три класса устройств.

**Материалы:** макет в Figma выдаётся преподавателем (одностраничный лендинг — услуга/продукт/мероприятие на выбор).

**Что нужно сделать:**
1. Сверстать лендинг с адаптацией под три контрольные точки:
   - мобильный: до 767px;
   - планшет: 768px – 1199px;
   - десктоп: от 1200px.
2. Основная структурная сетка страницы (расположение крупных блоков: шапка, основная секция (герой), карточки услуг/товаров, футер и т.д.) — через **CSS Grid** (`display: grid`, `grid-template-columns`, `grid-template-rows`, `gap`, `grid-column`/`grid-row`).
3. Раскладка внутри отдельных компонентов (например, содержимое одной карточки, навигационное меню, кнопки с иконкой) — через **Flexbox**.
4. Меню должно визуально превращаться в «гамбургер» на мобильной ширине (иконку можно взять готовую или нарисовать через `<span>` + CSS или SVG). **JavaScript-логику клика реализовывать не обязательно** — только то, как это должно выглядеть визуально (пункт 4 из требований проверяется по CSS, не по функциональности).
5. Добавить форму обратной связи: минимум поля «Имя», «Email», «Сообщение» и кнопка «Отправить». Оформить `input`, `textarea`, `button` со стилями для обычного состояния, `:hover`, `:focus`. Отправка формы не реализуется  — проверяется только вёрстка.
6. Добавить `transition` и `transform` к некоторым элементам  — например, изменение цвета кнопки при наведении, или увеличение карточки при hover.

**Технические требования (обязательные):**
- Подход **Mobile First**: базовые стили (без медиазапроса) пишутся для мобильного экрана, затем добавляются `@media (min-width: 768px) { ... }` и `@media (min-width: 1200px) { ... }`, расширяющие/переопределяющие стили. Медиазапросы вида `@media (max-width: ...)`, написанные «от десктопа к мобильному», не принимаются.
- Обязательно использование и Grid, и Flexbox в одном проекте (Grid — для крупной сетки страницы, Flexbox — для компонентов). Проект, целиком сверстанный только на Flexbox без использования  `display: grid`, не засчитывается.
- Файлы: `task2/index.html`, `task2/style.css`. Изображения — либо ссылками, либо в подпапке `task2/img/`.
- Сходство с макетом Figma должно быть в разумных пределах: отступы, шрифты, цвета — близко к оригиналу (PixelPerfect не требуется, но пропорции и структура должны совпадать).
- Проверить вёрстку на телефоне или через DevTools (Ctrl+Shift+M) — не должно быть горизонтального скролла, элементы не должны вылезать за экран, размеры кнопок/полей — не менее 44×44px (touch-friendly).

**Что сдавать:** ссылку на макет Figma, использованный вами (если преподаватель выдавал несколько на выбор — указать, какой), и папку `task2/`.

**Критерии проверки:** есть все три контрольные точки, стили написаны mobile-first, используются и Grid, и Flexbox по назначению, форма и меню оформлены, нет горизонтального скролла на мобильной ширине.

## Лабораторная работа №6. Игра на Canvas («Змейка»)

**Цель:** освоить рисование на Canvas, игровой цикл через `requestAnimationFrame` и обработку клавиатуры.

**Что нужно сделать:**
Реализовать классическую «Змейку»:
1. `<canvas>` фиксированного размера (например, 400×400 или 600×600, с сеткой из клеток одинакового размера, например 20×20 клеток по 20px).
2. Змейка изначально состоит из 3 сегментов, движется в одну сторону.
3. Управление стрелками клавиатуры (`ArrowUp/Down/Left/Right`). ## Лабораторная работа №10–11. Zen-Money — полноценное full-stack приложение (2 занятия, «два в одном»)

**Цель:** написать **собственный** сервер на Node.js/Express с реальной базой данных (SQLite) и полноценный фронтенд к нему. Это объёмная лабораторная, объединяющая backend и frontend — оценивается как единая работа с двумя равнозначными частями.

> Почему не `json-server`: `json-server` подделывает REST API за вас — вы отправляете запрос и получаете ответ, не понимая, что происходит внутри. Цель этой лабораторной — самим написать то, что раньше делал `json-server` за вас, и увидеть API «изнутри».

### Часть 1 (занятие 10): backend — Express + SQLite

**Подготовка проекта:**
1. Создать папку `task8-9/server/`, внутри — `npm init -y`.
2. Установить зависимости: `npm install express better-sqlite3 cors`.
   - `express` — сам сервер;
   - `better-sqlite3` — работа с SQLite синхронно и просто (без промисов, что упрощает код для первого знакомства с БД);
   - `cors` — чтобы фронтенд (запущенный на другом порту/через Live Server) мог обращаться к серверу без блокировки браузером.

**Структура базы данных (создать при старте сервера, если таблиц ещё нет):**
```sql
CREATE TABLE IF NOT EXISTS categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  type TEXT NOT NULL CHECK(type IN ('income', 'expense'))
);

CREATE TABLE IF NOT EXISTS transactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  amount REAL NOT NULL,
  category_id INTEGER NOT NULL,
  date TEXT NOT NULL,
  comment TEXT,
  FOREIGN KEY (category_id) REFERENCES categories(id)
);
```
При первом запуске сервера, если таблица `categories` пустая, добавить программно 2-3 стартовые категории (например, «Еда» — expense, «Зарплата» — income), чтобы фронтенд сразу было с чем тестировать.

**Что нужно реализовать на сервере (`server.js` или разбито на файлы `routes/`, `db.js` — на ваш выбор структуры, но не всё в одном файле длиннее 150 строк):**

| Метод | Роут | Что делает |
|---|---|---|
| GET | `/categories` | вернуть все категории |
| POST | `/categories` | создать категорию (`name`, `type` в теле запроса) |
| GET | `/transactions` | вернуть все операции; поддержать query-параметры `?category_id=`, `?type=`, `?from=&to=` (диапазон дат) — фильтрация должна происходить **в SQL-запросе** (`WHERE`), не на клиенте |
| POST | `/transactions` | создать операцию (проверить, что `amount` — число больше 0, `category_id` существует — иначе вернуть статус `400` с телом `{ "error": "..." }`) |
| PUT | `/transactions/:id` | обновить операцию по id |
| DELETE | `/transactions/:id` | удалить операцию по id |

**Технические требования (обязательные):**
- Использовать middleware `express.json()` для разбора тела запроса и `cors()` — подключить глобально.
- Каждый роут обёрнут в `try/catch`, при ошибке — ответ со статусом `500` и понятным телом `{ "error": "..." }`, не «упавший» без ответа сервер.
- На несуществующий `id` (например, `DELETE /transactions/999`, которого нет) — ответ `404`, а не `200`/`500`.
- Валидация входных данных на **сервере обязательна**, даже если фронтенд тоже валидирует — сервер не должен доверять клиенту.
- Сервер запускается командой `node server.js` (или `npm start`, прописанной в `package.json`) на порту `3001`.
- В `server/README.md` — команды установки (`npm install`) и запуска.

**Как проверить сервер без фронтенда (обязательный шаг перед переходом к части 2):** протестировать все 6 роутов через Postman, Thunder Client (расширение VS Code) или просто `curl` — приложить в README скриншот или лог хотя бы одного успешного запроса каждого типа (GET/POST/PUT/DELETE).

### Часть 2 (занятие 11): frontend + фильтры + деплой связки

**Критерии проверки (единые для обеих частей):** сервер запускается и отвечает на все 6 роутов корректными статусами, валидация есть и на сервере, и на клиенте, фильтрация происходит через SQL-запрос (не `.filter()` на клиенте — это проверяется по коду), полный CRUD работает end-to-end через интерфейс, нет ошибок в консоли браузера и в терминале сервера при обычном сценарии использования.

## Общие правила для всех лабораторных работ

- Каждая лабораторная сдаётся **отдельными коммитами** (минимум 2–3 коммита с осмысленными сообщениями на каждую лабораторную — не один коммит «сделал всё»).
- Дедлайн — начало следующего занятия, если не оговорено иное. Лабораторная, сданная после начала следующего занятия, но до конца текущей недели, принимается с пометкой «сдано с опозданием» (влияет на итоговую оценку по накопительной системе — уточняется преподавателем отдельно).
- Списанный без понимания код (в том числе сгенерированный нейросетью без изменений и понимания) при неспособности объяснить его на устном опросе — не засчитывается. Использовать ИИ-инструменты как помощника — можно и не запрещается, но студент должен уметь объяснить каждую строчку своего кода.
- Все работы должны открываться и проверяться без дополнительной настройки окружения преподавателем, кроме случаев, явно описанных в задании (например, `npm install` + `npm run dev` для React/Next.js/Angular-проектов — это нормально и ожидаемо, инструкция по запуску должна быть в README).
